# Distribución de los 14 mods y del shaderpack Complementary Unbound usando Modrinth como CDN, sin violar licencias (API/CDN de Modrinth, licencias por mod, versiones actuales para 26.1/26.1.2, .mrpack como fuente de verdad, qué va al server)

## Recomendación
Modelo 'linkear, no hostear': el launcher descarga los 14 jars y el shaderpack directamente desde cdn.modrinth.com usando las URLs 'files[].url' que devuelve la API (verbatim, con %2B), con User-Agent identificable (ej. 'tobiastortosa/sobrinosdepepe-launcher/1.0.0 (email)') y verificando sha1+sha512 del manifest. Ningún archivo de terceros se re-hostea en el backend propio: para Complementary está prohibido (cláusula 1.2.d de su licencia 1.6/1.7), para Xaero solo estaría permitido con crédito y sin monetización, y para el resto (Apache/MIT/LGPL/GPL/CC-BY/PolyForm Shield) sería legal pero innecesario. Excepción: guardar un backup privado no distribuido de los jars (menos Complementary) por si un autor borra una versión. Formato del manifest = modrinth.index.json (superset con tus campos: grupos opcionales, versión mínima de launcher, etc.), generado exportando la instancia de referencia desde Prism Launcher 11 o Modrinth App a .mrpack; el backend guarda cada versión del .mrpack y el 'panel de mods' del admin se reduce a 'subir nueva versión del pack + ver diff', sin construir un navegador de mods dentro del launcher. No publicar el pack en Modrinth (ni unlisted): agrega moderación y exposición sin beneficio para 5-20 jugadores. Auto-update en el cliente: comparar sha1 de mods/ y shaderpacks/ contra el manifest, bajar lo faltante/cambiado y borrar jars no listados en la carpeta gestionada; NUNCA llamar a /version_files/update desde el cliente (para el hash de Iris 1.10.9 devuelve Iris 1.11.3, que exige Sodium 0.9.x inexistente para MC 26.1 y rompería el pack); ese endpoint se usa en batch (1 request) desde el admin como aviso, y el admin fija version IDs. Shaders: grupo opcional 'Shaders' en el manifest, default OFF; el launcher baja ComplementaryUnbound_r5.9.zip (o r5.8.1) a shaderpacks/ y un toggle escribe config/iris.properties (enableShaders=true|false, shaderPack=ComplementaryUnbound_r5.9.zip); jamás modificar el contenido del zip. Pantalla 'Acerca de / Créditos' obligatoria con links a la página oficial de cada mod y a https://www.complementary.dev/ (cumple la condición de crédito de Xaero fuera de CF/Modrinth, la 1.2.a de Complementary si algún día se activa por defecto, y los avisos de MIT/Apache/LGPL/GPL/PolyForm; incluir textos de licencia o URLs). Versiones: recomendado subir el CLIENTE a MC 26.1.2 (mismo protocolo 775 que el server 26.1) con Sodium 0.9.1 + Iris 1.11.3 + Reese's 2.2.3 + Sodium Extra 0.9.3 + ZoomX 26.1.2 y el resto igual, probándolo antes en la instancia de referencia; si no, mantener 26.1 con el set actual, que ya es el máximo consistente, y renombrar los 3 archivos mal nombrados. Eliminar MapLink (no se usa, GPL, environment '*' y unsupported en server). Server (Minehost): si es Fabric, solo fabric-api + player-revive (+ lithium/modernfix opcionales, xaero opcional para enforce); si es vanilla/Paper, usar el datapack simple_revive_v3.0_mc26.1.zip; nunca copiar sodium/iris/sodium-extra/reeses/zoomx/maplink. Generar la lista del server desde el mismo index (env.server != unsupported).

## Hallazgos (25)

1. [high] Rate limit de api.modrinth.com: 300 requests/min por IP, igual con o sin token. Verificado hoy en los headers de respuesta: X-Ratelimit-Limit: 300, X-Ratelimit-Remaining, X-Ratelimit-Reset (segundos). Para más cupo hay que contactar a soporte. El CDN (cdn.modrinth.com) no devuelve headers de ratelimit.
   - fuente: https://docs.modrinth.com/api/ (sección Ratelimits) + headers observados hoy en GET https://api.modrinth.com/v2/project/P7dR8mSH y POST /v2/version_files
   - notas: Para 5-20 jugadores es irrelevante (2-3 requests por arranque). Ojo si varios jugadores comparten IP (LAN): el límite es por IP.

2. [high] Modrinth exige un User-Agent identificable en la API: 'You must provide a uniquely-identifying User-Agent'. Formatos recomendados: 'github_username/project_name/1.56.0' y mejor aún con contacto '(launcher.com)' o '(contact@launcher.com)'. UA genérico tipo okhttp/4.9.3 está desaconsejado.
   - fuente: https://docs.modrinth.com/api/ (sección User Agents)
   - notas: Usar el mismo UA para el CDN aunque no esté exigido explícitamente. Ej.: 'tobiastortosa/sobrinosdepepe-launcher/1.0.0 (contacto)'.

## Riesgos
- Un autor puede borrar una versión/proyecto de Modrinth y la URL del CDN deja de existir (permanencia no documentada; Cache-Control: no-store). Mitigar con job de HEAD periódico sobre el manifest + alerta al admin; para Complementary no hay mirror legal posible, solo cambiar de versión.
- La licencia de uso de la API de Modrinth es 'revocable' y el ToS incluye cláusula de indemnización: el launcher debe poder cambiar de fuente (GitHub releases propios para los mods con licencia libre) si Modrinth cambia reglas.
- Auto-update ingenuo basado en /version_files/update rompe cadenas de dependencia (caso real: Iris 1.11.3 ↔ Sodium 0.9.x solo para 26.1.2; Reese's 2.2.3 exige sodium >=0.9.1). Las actualizaciones deben ser curadas y probadas por el admin.
- Xaero (All Rights Reserved): el permiso de modpack exige crédito con link accesible fuera de CF/Modrinth, nombre no confundible y prohíbe monetizar fuera de CF/Modrinth sin permiso escrito. Si el server/launcher acepta donaciones, rangos pagos o banners, hay que pedirle permiso al autor (él mismo dice que suele darlo).
- Complementary: si el shaderpack queda en overrides/ del .mrpack o se sirve desde el backend propio se viola la cláusula 1.2.d; si se activa por defecto sin acreditar, la 1.2.a; si se toca el contenido del zip, la 1.2.c. Las licencias son por versión (2.2): revisar License.txt en cada upgrade.
- LGPL/GPL (iris, lithium, cloth, modernfix, sodium-extra, maplink, sound-physics): al no re-hostear el riesgo es mínimo, pero la pantalla de créditos debe incluir licencia y link al código fuente por prolijidad.
- Upgrade del cliente a 26.1.2 con Sodium 0.9.1/Iris 1.11.3 no fue probado en runtime hoy; posible incompatibilidad con shaders o con mods que declaran minecraft '26.1' exacto (zoomx) si se olvida cambiarlos.
- Si Minehost actualiza el server a 26.2 (protocol 776), todo el pack debe rearmarse (Xaero hoy declara <26.2.0).
- Sound Physics Remastered para 26.1 solo existe en canal beta (1.5.1+26.1.2): posibles bugs; no hay release estable.
- Rate limit de 300 req/min por IP compartida: irrelevante para 5-20 usuarios, pero un bug de reintentos en loop podría hacer que Modrinth bloquee la IP del backend o de un jugador.
- No se puede saber por el ping si el server de Minehost es Fabric, vanilla o Paper (MOTD 'A Minecraft Server'); si no es Fabric, la idea de 'mods server-side' cambia por completo (datapack Simple Revive).
- El .mrpack exportado por Prism solo incluye en files[] lo que matchea por hash: el shaderpack extraído en carpeta o jars renombrados con contenido distinto pueden caer en overrides sin que el admin lo note.

## Preguntas para el usuario
- ¿El server de Minehost corre Fabric (con fabric-api y player-revive instalados como mods) o vanilla/Paper con el datapack de Simple Revive? Cambia qué mods 'server-side' hay que gestionar y si hace falta Fabric en el server.
- ¿Vas a monetizar de alguna forma el launcher o el server (donaciones, rangos, banners/sponsors)? Xaero solo permite monetizar vía CurseForge/Modrinth sin permiso escrito; si la respuesta es sí, hay que pedirle permiso al autor por mensaje privado.
- ¿Querés subir el cliente a MC 26.1.2 (mismo protocolo 775 que el server 26.1) para poder usar Sodium 0.9.1 + Iris 1.11.3 + Reese's 2.2.3 + Sodium Extra 0.9.3, o preferís quedarte en 26.1 con el set actual (que ya es el máximo consistente)?
- ¿Tenés planes de actualizar el server a 26.2 en el corto plazo? Implica rearmar todo el pack (protocol 776) y esperar build de Xaero para 26.2.
- ¿MapLink se queda o se saca del pack? Hoy su config ignora el server actual (no se usa), es GPL y 'unsupported' en server.
- Shaders: ¿preferís un toggle 'Shaders' en el launcher que escribe iris.properties (default OFF), o solo dejar el zip en shaderpacks/ para que cada jugador lo active desde el menú de Iris? Si querés que venga activado por defecto, hay que acreditar visiblemente a Complementary en el launcher.

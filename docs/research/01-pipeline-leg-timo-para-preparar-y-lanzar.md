# Pipeline legítimo para preparar y lanzar Minecraft 26.1 + Fabric Loader 0.19.2 en Windows desde un launcher de terceros (descarga desde CDNs oficiales, sesión offline, login Microsoft, tamaño de la primera descarga y formato .mrpack como manifest)

## Recomendación
Usar el pipeline estándar de los launchers open source (Prism/HMCL) tal cual, sin inventar nada: (1) leer version_manifest_v2.json → 26.1.json (o 26.1.2.json si actualizan el server) y descargar client.jar, las 75 libraries con rules Windows y los 4750 assets del index 30 desde piston-data / libraries.minecraft.net / resources.download.minecraft.net, verificando sha1, con 8-16 descargas concurrentes y reanudación; (2) descargar el perfil Fabric desde meta.fabricmc.net (pinnear loader exacto, hoy 0.19.2 funciona y 0.19.5 es el stable) y hacer el merge inheritsFrom (mainClass KnotClient, libs Fabric al frente del classpath, -DFabricMcEmu como un solo argv); no hay intermediary que bajar en 26.x; (3) Java aislado en <instancia>/runtime: Temurin JRE 25 zip (58.5 MB, 1 request, sha256) como opción más simple, o java-runtime-epsilon de Mojang (25.0.1, 411 archivos, 80.8 MB con lzma) si querés seguir 1:1 al launcher oficial; (4) JVM args = los "default-user-jvm" de Mojang (-Xms2G -Xmx4G -XX:+UseZGC -XX:+UseCompactObjectHeaders -XX:+AlwaysPreTouch -XX:+UseStringDeduplication) + los jvm obligatorios del JSON (--sun-misc-unsafe-memory-access=allow, --enable-native-access=ALL-UNNAMED, los -D de natives) con un selector de RAM 4/6/8 GB; (5) sesión offline con UUID v3 = MD5("OfflinePlayer:"+name), accessToken opaco, clientId/xuid vacíos, y nombres EXACTOS (PEPE, Chichon, Titit0N, Luquitas1410) para que se conserven los playerdata del server; (6) formato de pack = .mrpack estándar (modrinth.index.json con sha1+sha512, env client/server, downloads en cdn.modrinth.com; configs y options.txt en overrides/, shaderpack como file env client=optional), y un manifest propio mínimo del launcher encima (versión del pack, URL del .mrpack, sha512, versión mínima del launcher, IP del server) — así el pack también se puede importar en Prism/Modrinth App y desplegar en el server con mrpack-install; (7) dejar el login Microsoft fuera del MVP (el server corre online-mode=false y las cuentas son TLauncher free) pero diseñar el módulo de auth con una interfaz que permita agregar el flujo MS→XBL→XSTS→login_with_xbox más adelante, y si hay chance de pasar a premium, enviar el formulario aka.ms/mce-reviewappid al inicio porque la aprobación es opaca y puede tardar semanas. Primera descarga ≈ 645-690 MB / ~5,000 archivos: 3-5 min a 50 Mbps con concurrencia; las actualizaciones posteriores son solo el delta del pack.

12. [high] Sesión offline: la fórmula estándar es UUID v3 = MD5("OfflinePlayer:" + nombre) con bits de versión/variante ajustados (equivale a Java UUID.nameUUIDFromBytes). Calculado en Python hoy: PEPE → 7a067f19-b48d-3c6e-9039-8f37f64def1f; Chichon → 5f1bb3e1-3a21-3c39-a409-e50842f7df31; Titit0N → 7bc394ba-c092-3432-b0b3-57a16c894f33; Luquitas1410 → 9c4d6396-daf9-3c3c-9eb3-93fe87cb87b7. El UUID que TLauncher usa para PEPE (5b071e1f-3a11-4f28-9c68-a6321cadc031) NO coincide: es un UUID versión 4 (aleatorio), así que TLauncher no aplica la fórmula OfflinePlayer (probé también variantes de mayúsculas y sin prefijo: ninguna coincide).
   - fuente: Cálculo local con Python hashlib/uuid; fórmula documentada en https://minecraft.wiki/w/Universally_unique_identifier ('UUID version 3, generated from the MD5 hash of OfflinePlayer:<username>')
   - notas: Es indistinto para el server: con online-mode=false el servidor vanilla ignora el UUID que manda el cliente y genera el suyo con la misma fórmula a partir del nombre (fuentes: hilo SpigotMC 'How can I make the UUID of the player on the offline server match the UUID of his client' y resultados de búsqueda; confirmación indirecta, confianza media-alta). Por eso los playerdata del server están bajo 7a067f19-... y se conservan mientras el nombre sea EXACTAMENTE igual (case-sensitive: 'Pepe' ≠ 'PEPE'). El launcher debería usar la fórmula v3 (queda consistente con el server y con cualquier herramienta externa).

[medium] Argumentos de sesión offline en 26.1: --accessToken acepta cualquier string no vacío (el cliente solo lo envía a los servicios de Mojang, que devuelven 401 como se ve en el log de TLauncher); --clientId y --xuid son opcionales (el launcher oficial pasa un clientId base64 y el XUID de Xbox; Prism/HMCL pasan vacío o un valor arbitrario para cuentas offline); el juego no valida ninguno localmente. En 26.1 desapareció --userType, así que no hay que decidir 'legacy' vs 'msa'. sessionserver.mojang.com devuelve 204 (sin perfil) para el UUID offline → sin skin propia: el cliente usa el skin default (Steve/Alex según hash del UUID). El servidor offline también sirve el perfil sin texturas.
   - fuente: Args verificados en https://piston-meta.mojang.com/v1/packages/c27af223100c5a1a7c986b361170bc8bd71ff3e1/26.1.json ; https://sessionserver.mojang.com/session/minecraft/profile/5b071e1f3a114f289c68a6321cadc031 devolvió HTTP 204 hoy; comportamiento de clientId/xuid = conocimiento previo de Prism/HMCL.
   - notas: El mod 'tlskincape' que inyecta TLauncher es lo que hoy les da skins/capas; sin TLauncher las pierden. Si las skins importan, la salida limpia es un mod server-side tipo SkinsRestorer (tiene build Fabric) o un mod cliente de skins offline; no lo verifiqué hoy (confianza baja).

[high] Flujo premium completo (verificado hoy en minecraft.wiki): a) OAuth2 MS (authorization code o device code en login.microsoftonline.com/consumers/oauth2/v2.0/{authorize|devicecode|token}) → access_token + refresh_token. b) POST https://user.auth.xboxlive.com/user/authenticate {Properties:{AuthMethod:'RPS', SiteName:'user.auth.xboxlive.com', RpsTicket:'d=<access_token>'}, RelyingParty:'http://auth.xboxlive.com', TokenType:'JWT'} → Token + DisplayClaims.xui[0].uhs. c) POST https://xsts.auth.xboxlive.com/xsts/authorize {Properties:{SandboxId:'RETAIL', UserTokens:[<xbl>]}, RelyingParty:'rp://api.minecraftservices.com/', TokenType:'JWT'} → XSTS token (errores XErr 2148916233 = sin cuenta Xbox, 2148916238 = menor sin familia, 2148916235/6/7 = región/verificación). d) POST https://api.minecraftservices.com/authentication/login_with_xbox {identityToken:'XBL3.0 x=<uhs>;<xsts>'} → access_token Bearer, expires_in 86400. e) GET https://api.minecraftservices.com/entitlements/mcstore (vacío = no tiene el juego). f) GET https://api.minecraftservices.com/minecraft/profile → id (uuid), name, skins, capes. Con eso se rellenan ${auth_uuid}, ${auth_player_name}, ${auth_access_token}; ${auth_xuid} sale del claim xid del XSTS.
   - fuente: https://minecraft.wiki/w/Microsoft_authentication
   - notas: Requisitos extra citados por la wiki: el JWT de Minecraft se puede validar con la clave pública de Mojang; usuarios de Game Pass deben haber abierto una vez el launcher oficial para tener perfil. Para el caso de uso actual (server online-mode=false, cuentas TLauncher free) este flujo no aporta nada hasta que el server pase a online-mode=true.

17. [high] Formato .mrpack (verificado hoy en el Help Center de Modrinth): ZIP (MIME application/x-modrinth-modpack+zip) con modrinth.index.json UTF-8 en la raíz. Campos: formatVersion (number, actualmente 1), game ('minecraft'), versionId (string), name (string), summary (opcional), files[] y dependencies. Cada file: path (relativo al dir del juego, ej. mods/x.jar; no puede contener '..' ni empezar con letra de unidad), hashes {sha1, sha512} (ambos requeridos, otros opcionales), env {client, server} opcional con valores 'required' | 'optional' | 'unsupported', downloads[] (URLs HTTPS; dominios permitidos SOLO cdn.modrinth.com, github.com, raw.githubusercontent.com, gitlab.com; el cliente debe seguir redirects 3xx), fileSize (bytes, para progreso). dependencies: claves permitidas minecraft, forge, neoforge, fabric-loader, quilt-loader (ej. {minecraft:'26.1', fabric-loader:'0.19.2'}). Carpetas: overrides/ (base), client-overrides/ y server-overrides/ (opcionales, se aplican después y sobreescriben overrides/).
   - fuente: https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack
   - notas: Los 14 mods del usuario ya tienen URL cdn.modrinth.com/data/<project>/versions/<versionId>/<file> con sha1+sha512 expuestos por la API (verifiqué hoy con https://api.modrinth.com/v2/project/fabric-api/version?game_versions=["26.1"]&loaders=["fabric"] → 25 versiones; fabric-api 0.155.2+26.1.2 = versionId uLkEd5dr, 2,520,724 B, hashes sha1+sha512). Configs (iris.properties, sodium-options.json, xaero/, sound_physics_remastered/, options.txt) van en overrides/config y overrides/options.txt; el shaderpack Complementary Unbound puede ir como file con env client=optional apuntando a su release en cdn.modrinth.com (no rehostearlo).

## Riesgos
- El login Microsoft para launchers nuevos requiere aprobación manual de Mojang (aka.ms/mce-reviewappid); sin ella login_with_xbox devuelve 403. No hay SLA publicado; la comunidad reporta semanas o meses y rechazos. Si el proyecto decide soportar cuentas premium, esto es el camino crítico.
- Con online-mode=false el server acepta a cualquiera que envíe un nombre en la whitelist; la 'autenticación' del launcher propio no protege al server frente a un cliente modificado. La whitelist por nombre + IP del panel de Minehost es un mitigador, no una autenticación real. (Fuera del alcance de este tema, pero condiciona el diseño del backend.)
- Sin TLauncher desaparece 'tlskincape': los jugadores offline pierden skins y capas (sessionserver devuelve 204 para UUIDs offline). Puede generar quejas el primer día; requiere mod server-side de skins o aceptar Steve/Alex.
- Los playerdata del server están keyed por UUID v3 derivado del nombre exacto (case-sensitive). Si el registro del launcher permite otro casing o renombrar, el jugador pierde inventario/posición. Hay que fijar los nombres existentes y validar [A-Za-z0-9_]{3,16}.
- 26.1 ya tiene 26.1.1/26.1.2 y 26.2 encima; el pack queda pinneado y el server de Minehost debe correr exactamente la misma versión de protocolo. Un update automático del server por parte del hosting rompería la conexión hasta re-pinnear el pack.
- Fabric Loader 0.19.2 no es el stable actual (0.19.5). Algún mod nuevo puede exigir loader más nuevo; el manifest debe permitir subir el loader sin cambiar el game version.
- El JRE de Mojang viene como 411 archivos, muchos solo en .lzma: en .NET hace falta un decoder LZMA externo (SharpCompress/LZMA SDK) o descargar raw (+24 MB). Temurin evita esto pero depende de GitHub Releases (bloqueado en algunas redes/antivirus).
- Los 4,750 assets y los sha1 por archivo hacen que la instalación sea sensible a antivirus (Defender escanea cada jar/dll) y a redes con proxy; hay que implementar reintentos, verificación y un 'reparar instalación'.
- Licencias: Sodium (Polyform Shield), Xaero's (All Rights Reserved) y Complementary no admiten rehosting; si algún día un mod sale de Modrinth o cambia de URL, el .mrpack deja de instalar hasta actualizarlo (los archivos de versiones viejas en cdn.modrinth.com suelen quedar, pero no está garantizado).
- Un .exe de launcher sin firma Authenticode dispara SmartScreen/Defender en Windows 11; el instalador y el auto-update del propio launcher necesitan firma (certificado EV o Azure Trusted Signing) o instrucciones claras para los 5 amigos.
- El formulario de Mojang y la documentación de client.json no están completamente disponibles sin JS/documentación oficial; los detalles de clientId/xuid en offline y los campos exactos del formulario son conocimiento previo (confianza media).

## Preguntas para el usuario
- ¿Los 5 jugadores tienen (o van a tener) cuentas Minecraft premium/Microsoft? Si la respuesta es no y el server sigue en online-mode=false, el launcher solo necesita sesión offline y el módulo Microsoft se posterga; si es sí, hay que pedir la aprobación de Mojang (aka.ms/mce-reviewappid) desde el día 1 y el diseño de cuentas cambia por completo.
- ¿Qué versión exacta corre hoy el server de Minehost (26.1, 26.1.1 o 26.1.2) y estás dispuesto a actualizar server + pack a 26.1.2 antes del lanzamiento del launcher? Define qué version JSON se pinnea.
- ¿Necesitás conservar los inventarios/progreso actuales? En ese caso los usernames del launcher deben ser exactamente PEPE, Chichon, Titit0N, Luquitas1410 (y el quinto), con el mismo casing, y el registro no puede permitir renombrar.
- ¿Las skins personalizadas son un requisito para tus amigos (hoy las da TLauncher)? Si sí, hay que agregar un mod server-side de skins o un mod cliente al pack, y eso cambia la lista de mods y la config del server.
- ¿Cuánta RAM tienen las PCs de los jugadores (8 GB vs 16 GB+)? Define el -Xmx por defecto (4G vs 6G) y si el selector de RAM es necesario en la primera versión.
- ¿Preferís que Java se baje del CDN de Mojang (idéntico al launcher oficial, 411 archivos, requiere LZMA) o un zip de Temurin (1 archivo desde GitHub)? Impacta en dependencias del launcher y en redes que bloquean GitHub.

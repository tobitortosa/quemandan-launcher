# Stack del launcher de escritorio (Windows-first): C#/.NET 10 (WPF vs Avalonia vs WinUI 3) + CmlLib.Core + Velopack, vs TypeScript (Electron + @xmcl/*) y Tauri 2; firma de código y runtime

## Recomendación
Recomendación principal (Plan A): C# / .NET 10 (LTS hasta 2028-11) + Avalonia 12.1.2 (tema Fluent, MVVM con CommunityToolkit.Mvvm) + CmlLib.Core 4.0.6 + Velopack 1.2.0, publicado self-contained en CARPETA (sin PublishSingleFile/IncludeNativeLibrariesForSelfExtract, excluyendo *.pdb nativos) y empaquetado con vpk pack (Setup.exe per-user sin admin, deltas automáticos). Fuente de updates: GitHub Releases público vía GithubSource, o SimpleWebSource apuntando a un endpoint estático del backend Next.js que ya tiene el usuario (así el mismo backend sirve manifest de mods + releases del launcher). Justificación: (1) el usuario ya tiene .NET 10 + VS 2026 y ChatGPT le sugirió C#; Avalonia da UI moderna out-of-the-box (WPF se ve viejo sin librerías de terceros y no trimmea; WinUI 3 arrastra Windows App Runtime y churn: 2.0 en abril 2026, 1.8 EOL sept 2026); (2) CmlLib.Core, verificado hoy empíricamente, parsea 26.1 (java-runtime-epsilon/25, assets 30, sha1 del client coincide), instala Fabric 0.19.2 desde meta.fabricmc.net, descarga el Java 25 de Mojang y arma el proceso; con offline session y login Microsoft opcional (WebView2, client id del launcher oficial) ya resuelto; (3) tamaño: ~110 MB carpeta self-contained Avalonia (medido) vs 120 MB de un solo instalador NSIS de Electron hello world (medido) y 384 MB descomprimido; (4) Velopack está activo (commit 2026-09-03), cubre instalador + auto-update + delta + firma en un solo tool y soporta net10.0. Diseño del núcleo: usar CmlLib para parsing de versiones, perfil Fabric, resolución de Java y MinecraftProcessBuilder, pero escribir la capa de descarga propia (o envolver ParallelGameInstaller) con reintentos exponenciales, verificación SHA1/SHA-256, descarga a archivo temporal + rename, y un manifest propio (JSON firmado con hashes) para mods/configs/shaderpacks tomando las URLs de cdn.modrinth.com. Dos gotchas obligatorios: (a) instalar vanilla 26.1 con InstallAsync("26.1") y para el perfil Fabric quitar JavaFileExtractor de launcher.FileExtractors, porque si no baja jre-legacy (150 MB inútiles); (b) MSession.CreateOfflineSession genera UUID aleatorio → asignar UUID = UUIDv3(md5 "OfflinePlayer:<nombre>") para que sea estable e igual al que calcula el server offline. Firma: para un individuo en Argentina Azure Artifact Signing NO está disponible (individuos solo EE.UU./Canadá; organizaciones solo en la lista de países). Opciones reales: Certum Open Source Code Signing cloud (~USD 58, si el launcher es open source) o SSL.com IV (~USD 129/año + eSigner o YubiKey USD 379), ambos con renovación anual (validez máx. 460 días). Si no se firma: aceptar el aviso SmartScreen en cada Setup.exe nuevo (la reputación con 5-20 usuarios nunca se acumula), documentar 'Más información → Ejecutar de todas formas', publicar SHA-256 y avisar que Smart App Control en Win11 puede bloquear; el auto-update por Velopack minimiza cuántas veces los jugadores bajan un Setup.exe nuevo. Plan B (si el usuario prefiere mantener TypeScript): Electron 44 + electron-vite/React + @xmcl/core 2.16 / @xmcl/installer 6.3 (workflows createFabricInstallWorkflow y createJavaRuntimeInstallWorkflow, con checksums y reintentos en las tasks 'files') + @xmcl/user offline() + electron-builder 26.16 NSIS + electron-updater 6.8.9 con provider GitHub y blockmap differential. Costos: ~120 MB por instalador, actualizar a electron-updater v28 exigirá firma (fail-closed) o una verify function custom, y el login Microsoft requiere @azure/msal-node propio (necesita client id propio y aprobación de Microsoft para la API de Minecraft). Dentro de .NET, el fallback si Avalonia frustra es WPF + WPF-UI (misma arquitectura, mismo CmlLib/Velopack, 65 MB single-file o 146 MB carpeta). Descartar Tauri 2: exige Rust + C++ build tools que el usuario no tiene, no hay lib madura de launcher en Rust, updater sin deltas y con claves minisign que si se pierden bloquean updates para siempre.

Precios de referencia verificados hoy: SSL.com IV (Individual Validation, sin empresa) USD 129/año (USD 96,75/año a 5 años) + almacenamiento obligatorio en token FIPS (YubiKey +USD 379, envío desde EE.UU.) o eSigner cloud por suscripción; Certum 'Open Source Code Signing in the Cloud' desde USD 58 (solo personas físicas, CN con prefijo 'Open Source Developer', SimplySign cloud, límite 5.000 firmas/mes); Sectigo OV vía resellers ~USD 219/año (requiere empresa); DigiCert OV ~USD 400, EV ~USD 685.
   - fuente: https://www.ssl.com/products/software-integrity/code-signing/iv/ ; https://certum.store/open-source-code-signing-on-simplysign.html ; https://www.ssldragon.com/ssl-certificates/code-signing/ ; https://www.digicert.com/blog/understanding-the-new-code-signing-certificate-validity-change
   - notas: Precios de resellers varían; no confirmé si Certum exige un repo open source público (probable) ni la disponibilidad de validación de identidad para argentinos en SSL.com (en general aceptan pasaporte, pero no lo verifiqué).

22. [high] SmartScreen (doc Microsoft actualizado 2026-08-17): evalúa reputación del publisher (certificado) y del hash del archivo. Sin firma: aviso 'Windows protected your PC' y la reputación arranca de CERO en CADA versión nueva (no se transfiere). Con OV/EV: también aparece el aviso al principio pero muestra el nombre verificado y la reputación se acumula en el certificado y pasa a versiones nuevas. 'EV certificates no longer bypass SmartScreen... Paying a premium for EV solely to avoid SmartScreen warnings is no longer justified.' Reputación: 'no exact threshold, but it can take several weeks and hundreds of clean installs from a wide audience' — con 5-20 jugadores NUNCA se va a acumular. No hay mecanismo de envío manual para consumidores. Además: en Windows 11 Smart App Control puede BLOQUEAR directamente ejecutables sin firma y sin reputación.
   - fuente: https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation
   - notas: Mitigación práctica sin firma: instrucciones en la web/Discord con captura ('Más información' → 'Ejecutar de todas formas'), distribuir por HTTPS y publicar SHA-256 del Setup.exe, mantener nombre/ícono estables, y evitar cambiar el instalador seguido (cada Setup.exe nuevo = hash nuevo). El auto-update de Velopack corre desde la app ya instalada, así que el aviso SmartScreen aparece solo con el Setup.exe inicial (los updates no pasan por Mark-of-the-Web) — esto último es conocimiento previo, confianza media.

## Riesgos
- CmlLib.Core lleva ~11 meses sin release (4.0.6, 2025-09-24) y el repo sin push desde 2025-10-18: si Mojang cambia el formato del version JSON o del manifest de Java, hay que forkear o parchear. Mitigación: el launcher depende de CmlLib solo para parsing/launch, con la descarga desacoplada.
- Gotcha verificado: InstallAsync sobre el perfil Fabric descarga jre-legacy (Java 8, 150 MB) además de java-runtime-epsilon; si no se filtra el JavaFileExtractor, cada instalación limpia desperdicia 150 MB.
- CmlLib no tiene reintentos ni reanudación visibles en su instalador y hay un issue abierto de descargas lentas (#112): sin capa propia de retry/backoff los primeros 670 MB (assets 456 MB) van a fallar en conexiones flojas.
- Sin firma de código, SmartScreen mostrará 'Windows protected your PC' en cada Setup.exe nuevo y Smart App Control (Win11) puede bloquear directamente; con 5-20 usuarios la reputación nunca se acumula. Azure Artifact Signing no está disponible para individuos fuera de EE.UU./Canadá ni para organizaciones argentinas.
- Certificados comerciales: validez máxima 460 días desde 2026-03-01 → costo recurrente anual (USD 58-130 + hardware/cloud) y trámite de identidad; si se cambia de certificado la reputación se reinicia.
- Self-contained + PublishSingleFile con auto-extracción de nativos tiene historial de falsos positivos de Defender; usar publish en carpeta. Avalonia arrastra 105 MB de .pdb nativos (libSkiaSharp.pdb/libHarfBuzzSharp.pdb) al publish si no se excluyen.
- Si se elige Electron: 120 MB por instalador, electron-updater v28 pasará a fail-closed sin firma (auto-update roto para apps sin firmar), y el login Microsoft exige client id propio + aprobación de Microsoft para la API de Minecraft.
- Avalonia 12 es reciente (abril 2026): posibles bugs de control/tema en 12.1.x; hay rama 11.3 LTS como fallback (11.3.20). El usuario no conoce XAML/MVVM: curva de mantenimiento aunque Claude escriba el código.
- GitHub Releases sin token tiene límite de 60 requests/hora/IP y un repo privado obligaría a embeber un token en el cliente; conviene repo público solo de releases o servir releases.json desde el backend propio.
- Minecraft ya está en 26.2 (junio 2026) y 26.3 en pre-release; el modpack está anclado a 26.1 + Fabric 0.19.2: el manifest del launcher debe fijar versiones exactas y Sodium/Iris/etc. deben re-verificarse cuando se migre de versión de juego.
- Windows 32-bit no tiene java-runtime-epsilon (solo x64/arm64): el launcher debe detectar arquitectura y rechazar x86.

## Preguntas para el usuario
- ¿Tenés (o vas a tener) una empresa registrada en alguno de los países elegibles para Azure Artifact Signing (EE.UU., Canadá, UE, UK, Australia, NZ, Japón, Corea, Singapur, Suiza, Noruega, Israel), o vas como persona física en Argentina? Define la estrategia de firma: Artifact Signing (~USD 10/mes) vs certificado IV/Open Source (Certum ~USD 58 / SSL.com ~USD 129/año) vs sin firma con instrucciones anti-SmartScreen.
- ¿El launcher va a ser open source (repo público)? Habilita el certificado 'Open Source Developer' de Certum (más barato) y permite GitHub Releases público como fuente de updates sin tokens.
- ¿Preferís mantener a largo plazo C# + Avalonia (XAML/MVVM, nuevo para vos) o TypeScript + Electron (tu stack, pero 120 MB por instalador y auto-update que exigirá firma en electron-updater v28)? Es la decisión que más cambia el plan.
- ¿Querés login Microsoft opcional para jugadores con cuenta premium (skins oficiales, futura migración a online-mode=true)? Cambia el módulo de auth (WebView2 + CmlLib.Core.Auth.Microsoft) y el modelo de cuentas del backend.
- ¿Dónde vas a hostear los releases del launcher y el manifest de mods: GitHub Releases o tu propio backend Next.js/servidor estático? Define GithubSource vs SimpleWebSource y si el manifest se firma con clave propia.
- ¿Hace falta soportar macOS/Linux en algún momento? Si sí, Avalonia se justifica aún más y WPF queda descartado; si es Windows-only para siempre, WPF + WPF-UI vuelve a ser una opción válida.
